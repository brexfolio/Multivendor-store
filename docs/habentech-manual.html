Habentech — Complete Feature Manual

Everything about how the app works: the customer store, the admin dashboard, and especially inventory & stock management.

🏠 What is Habentech?

A Telegram Mini App electronics store + owner dashboard, running through the bot @pixelsrbot at https://habentech.vercel.app.

It has two experiences in one codebase:

  • Store  Covers the customer store — browse, search, favorite, order, request, and sell devices.
  • Admin  Covers the owner's dashboard — products, orders, requests, sell-requests, inventory and settings.

👥 Who uses it

RoleAccessWhat they do
CustomerStore (Home / Sell / Favorites / Orders)Browse, order, request products, sell a device, accept offers.
Admin (you)All of the above + My Store dashboardFull management. Identified by ADMIN_TELEGRAM_ID.
Tip: The admin is the single Telegram user whose ID equals the ADMIN_TELEGRAM_ID env value — only they see the dashboard.

Note: The bottom nav is hidden here by design — you navigate back with the arrow, keeping focus on the product.

🛒 Order vs. Request

Two ways to get a product, depending on availability and stock.

Order Now Store

When a product is Available or Low Stock, customers can place an order:

Tap Order Now→ Choose quantity→ Confirm→ Order created (Pending)→ Admin gets bot buttons

Request Product Store

Used when a product is not directly orderable, or the customer wants it set aside:

Tap Request Product→ Confirm request→ Admin notified in bot→ Admin marks status→ Customer notified automatically

The backend rejects requests for Sold / Unavailable / Out of Stock products (409).

❤️ Favorites

Save products you're interested in.

  • Tap the ♥ on any card or product page to add/remove.
  • The Favorites tab lists only the products you've saved, kept in the order you favorited them.
  • Favorites are stored locally on the device (per user).

💰 Sell a Device (Sell tab)

Customers can list a used device for the store to buy.

Multi-step wizard

1 · Brand & Model→ 2 · Condition→ 3 · Details (screen/storage…)→ 4 · Expected price→ 5 · Photos→ 6 · Review & submit
  • Photo rules: image files only, max 10MB each; uploads continue even if one file fails.
  • After review, the store can send an offer to the customer.
  • The customer sees offers in My Sell Submissions and can Accept or Reject.

🏷️ Manage Products

Create, edit and publish products — the core of the store.

Creating / editing

  • Set name, category, price, currency, condition, description, and specifications.
  • Upload multiple images.
  • Important: images are uploaded and posted to Telegram only when you Save/Publish — not before (saves bandwidth).

Publishing to the channel

Publishing posts the product to your configured Telegram channel (TELEGRAM_CHANNEL_ID) with a View Product button that deep-links into the Mini App.

📈 Inventory & Stock Management

The heart of the admin side. This section explains stock, transactions, and how stock auto-stays in sync with orders.

Stock is tracked per product

  • Each product has an inventory record with a total quantity.
  • Every change is recorded as a transaction (an audit trail).
  • Stock can never go below 0 (enforced in the database too, quantity >= 0).
TransactionEffectExamples
Add+ stockRestock from supplier, purchase
Remove− stockDamage, loss, manual adjustment
AdjustSet to a target numberStock count corrections
Sale− stock (auto)Completing an order
Return+ stock (auto)Cancelling/reversing an order

Manual stock actions (in-app)

Open a product in the Inventory section to:

  • Add stock — enter quantity, optional cost price & supplier. Preview shows the new total.
  • Remove stock — enter a reason from a list. Validated: you can't remove more than the current quantity (the input has a max and live preview).
  • Adjust stock — set the quantity to a specific number, with a required reason.

Every action is recorded to the transaction history for that product.

How an order changes stock (automation)

Order placed→ Admin taps Complete→ Sale transaction created→ Quantity reduced→ Availability updated
Idempotency guard: A unique database index (added via SQL) guarantees an order can only create one Sale and one Return — even if the admin taps Complete twice. No double stock deduction is possible.

Availability & low-stock

  • Availability auto-syncs with stock.
  • When stock hits 0 → availability becomes Out of Stock (not orderable).
  • Below the minimum stock level → flagged as Low Stock and a low-stock notification can be triggered.
For you (owner): The two unique index statements that protect stock live in supabase/schema_sell_and_inventory.sql and must be applied to the live Supabase database (SQL Editor). Git/Vercel deploys only ship the app code — the schema change is manual.

🤖 Telegram Bot Actions (Admin)

The bot @pixelsrbot notifies you of activity and lets you act without opening the dashboard.

EventButtons you seeResult

New order✅ Confirm · ✔️ Complete · ❌ CancelComplete adjusts stock, Cancel restores it

🔗 Sharing & Deep Links

  • Each product has a shareable link like: https://t.me/pixelsrbot/Habentech?startapp=product_<id>
  • Tapping it opens the Mini App directly on that product.
  • The channel's View Product button uses the same deep link.
  • Back from a deep link returns Home, not a blank page.
  • Sharing works via Copy Link, Telegram, WhatsApp, or the native share sheet.

🔒 Security

  • Server-side auth — every mutation verifies the Telegram init data (HMAC) on the server; forged requests are rejected.
  • Admin-only gated by ADMIN_TELEGRAM_ID — only you can open the dashboard or act on bot buttons.
  • Secrets stay server-side — bot token, service-role key, webhook secret are never sent to the browser.
  • Webhook verification — Telegram calls include a secret token the app validates.
  • No secrets in git — .env* is ignored; only the placeholder .env.example is tracked.

🚀 Deployment & Environment

Stack: Next.js 16 (App Router/Turbopack) · React 19 · TypeScript · Supabase · Telegram Bot API, deployed on Vercel.

Environment variables

TELEGRAM_BOT_TOKEN — bot token (server-only)
ADMIN_TELEGRAM_ID — your numeric user ID (admin)
TELEGRAM_CHANNEL_ID — channel the bot posts products to
TELEGRAM_WEBHOOK_SECRET — webhook verification secret
NEXT_PUBLIC_TELEGRAM_BOT_USERNAME — @pixelsrbot
NEXT_PUBLIC_TELEGRAM_APP_NAME — Habentech
NEXT_PUBLIC_APP_URL — https://habentech.vercel.app
NEXT_PUBLIC_SUPABASE_URL / ANON_KEY — Supabase (public)
SUPABASE_SERVICE_ROLE_KEY — Supabase admin (server-only)

Deploying

  • Commit & push → Vercel auto-deploys.
  • Database schema changes (SQL) are manual — run them in Supabase; git push does not touch the DB.
